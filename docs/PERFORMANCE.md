# بنچمارک پایهٔ بار (QA-08 — فاز ۱۳ / PH-07)

**تاریخ اجرا:** ۲۳ اکتبر ۲۰۲۶ · **اسکیما:** v9 · **محیط:** Windows 10 (10.0.19045)، Python 3.13.2، SQLite 3.45.3، دیسک محلی

**روش:** `.venv\Scripts\python.exe tools\benchmark.py --ops 2000 --reps 3 --json docs\bench_ph07_2026-10-23.json`
— دیتابیس موقت SQLite (بدون شبکه، بدون اثر روی نصب واقعی). هر بلوک سه بار اجرا و **میانه** گزارش می‌شود.
بلوک `referral_credit_trx` شامل `BEGIN IMMEDIATE` + trigger اتمیک + رسید `credit_log` است.
دو بلوک جدید PH-07: `concurrent_cycle` شبیه‌سازی ۲۰ چرخهٔ کانال با `ch_lock` + خواندن تنظیمات/مقالات از استخر DB
است؛ `mocked_http_pipeline` مسیر کشف → درج مقاله → ارسال را با `httpx.MockTransport` و ربات جعلی اندازه می‌گیرد.

**مقایسه با پایهٔ قبلی (اجرای تک‌مرتبه، اسکیمای v6):** `users_insert` ۶۷۷۴.۹ و `users_select`
۶۴۹۹۲.۵ بود (تفاوت ~۰٪ و ~−۶٪)؛ `articles_insert` ۳۱۵۵.۳ (اکنون −۱۷٪) و
`referral_credit_trx` ۶۵۲.۰ (اکنون +۱۷٪). این اختلاف‌ها در محدودهٔ نوسان میزبان/نسخهٔ Python/SQLite
هستند و هیچ بلوکی افت بیش از ~۲ برابر ندارد. دو بلوک `concurrent_cycle` و `mocked_http_pipeline`
پایهٔ قبلی ندارند و از این نسخه به بعد مبنای مقایسه‌اند.

**محدودیت‌ها:** `mocked_http_pipeline` تأخیر شبکهٔ واقعی، Telegram Bot API، محدودیت نرخ و
`PUBLISH_CONCURRENCY` را شبیه‌سازی نمی‌کند؛ فقط سربار هم‌روندی/DB/مسیر انتشار را نشان می‌دهد.
`concurrent_cycle` نیز پاسخ Telegram و AI را ندارد. این اعداد «پایهٔ نسبی» برای نصب تک‌فایلی SQLite
هستند، نه ظرفیت‌سنجی بار چند-کاربره یا D1.

**نحوهٔ مقایسه:** همان دستور را با همان `--ops 2000 --reps 3` تکرار کنید. افت بیش از ~۲ برابر در
هر بلوک یعنی regression — تا بررسی و رفع، استقرار را جلو نبرید. گزارش خام:
`docs\bench_ph07_2026-10-23.json`.
